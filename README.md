## Instructions for agents

This repository serves the following independent projects:

- **Lia-Project**
- **Lia Forge**
- **Lia Studio**
- **Lia Agent Hub**
- **Lia Model Lab**

When working in any of these projects:

1. Consult the research branch before starting research that may already exist or making technology, architecture, provider, model, tool, or licensing recommendations.
2. Search the Research Index first, then read the relevant source report and its metadata. Follow links to original repositories and sources when verification is needed.
3. Preserve the report's evidence, date, source commit/version, license, confidence, and status. Treat historical, incomplete, unverified, conflicting, or superseded findings accordingly; do not present them as current verified facts.
4. Cite the Lia-Research document IDs and paths in your project report or handoff so other agents can trace the basis for a recommendation.
5. **Read-only for project agents:** do not edit this repository or the research branch as part of work in another project. Do not switch, overwrite, or commit to the Research session's branch.
6. If research is missing, stale, contradictory, or needs deeper verification, record the gap in your project handoff and request follow-up research from the Research owner/session. Do not silently create a competing copy or modify the central reports.
7. Research findings are recommendations and evidence, **not implementation authorization**. Each project's responsible development workflow decides whether and how to adopt them. Do not modify another project's code or configuration based only on a research report.

## Research ownership and branch workflow

The Research session owns research maintenance and publication on `arena/7cf9c65e-lia-research`. Other agents and project sessions consume that material in read-only mode. This separation avoids concurrent edits and prevents project implementation work from disrupting ongoing research.

The repository is public so agents across the ecosystem can read it. Public availability does not mean that every finding is approved, current, or safe to adopt; follow the status and governance metadata in each report.

Until the research collection is deliberately integrated into `main`, use the explicit branch links above. Do not assume the repository root or `main` contains the current documentation.

## Scope

Lia-Research is a shared knowledge base, not a shared runtime, dependency, or code-integration repository. It records research, comparisons, source provenance, licensing considerations, risks, and recommendations for the Lia ecosystem while keeping the five product repositories independent.

## Contribution rule

Only the Research owner/session should maintain the central research collection unless the repository owner explicitly authorizes a separate contribution workflow. Never publish secrets, credentials, personal data, private logs, or unreviewed sensitive material.
